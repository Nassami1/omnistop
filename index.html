Goal

Ship a one-pool stop-loss and take-profit MVP on Reactive Lasna that turns a pool Sync event into an authenticated destination callback, with every leg observable.

Problem

A stop-loss normally needs a bot to poll prices, decide, and send a transaction. That adds a server to trust and a polling interval to lose. The pool already publishes its reserves on every swap, so the signal is already in the log.

Solution

Subscribe to the pair's Sync event from a reactive contract on Lasna. Decode reserve0 and reserve1, compute the reserve ratio, and compare it with the last breached ratio. When the move is at or past thresholdBps, request a callback to OmniStopExecutor.

The callback proxy injects the reactive address. The executor accepts only the configured proxy and reactive signer, so a direct caller cannot forge a fill.

Architecture

  1. Base Sepolia test pair emits Sync(uint112 reserve0, uint112 reserve1).
  2. OmniStopReactive on Lasna receives the log, computes the ratio, and calls requestCallbackV_1_0 on the system contract.
  3. CallbackProxy on Base Sepolia calls executeSwap with the reactive address in the first argument slot.
  4. OmniStopExecutor checks msg.sender and the injected address, then emits SwapExecuted.

Deployment order is reactive, executor, then setExecutor, because the executor pins the reactive address at construction.

Threshold math

price     = reserve1 * 1e18 / reserve0
moveBps   = abs(price - lastPrice) * 10000 / lastPrice
breach    if moveBps >= thresholdBps

The first Sync writes the baseline and returns. A breach writes the new baseline. A move inside the band leaves lastPrice alone, so a slow drift does not reset the stop.

The contract compares delta * 10000 >= lastPrice * thresholdBps to avoid an extra division. Integer math rounds down on both sides.

Latency method

Three timestamps matter: the origin receipt timestamp on Base Sepolia, the reactive transaction timestamp on Lasna, and the callback receipt timestamp on Base Sepolia. No block-number math is used on Base Sepolia.

The reactive contract emits LatencyMeasured(originTxHash, reactTs). The executor emits SwapExecuted(price, originTxHash, callbackTs, reactiveToCallbackMs). Full-loop latency is callbackTs - originTs, measured after the run from the two receipts with cast.

The current LogRecord ABI has no origin block timestamp. originTs therefore comes from the origin receipt, not from the reactive payload. The on-chain event records the reactive-to-callback leg it can prove. Cross-chain clock skew can make that leg larger than the same-chain full loop.

Risks

  • Test pair, not live liquidity. Base Sepolia has no official Uniswap V2 deployment, so the live run uses MockSyncPair. The Reactive path is real; the liquidity is simulated. Wire a real pair for production.
  • Reserve ratio is not a TWAP. One large swap can trigger or manipulate it. This is a signal MVP, not an oracle.
  • Callback gas. The proxy withholds gas for accounting. A failing callback still bills the executor. Fund the executor with destination ETH and raise gasLimit if needed.
  • Reactive fees. The Lasna contract needs REACT. A contract in debt receives no events.
  • No swap yet. executeSwap records the signal; swapViaRouter is a stub. Do not present this as a live stop order.
  • Cross-chain clock skew. Lasna and Base timestamps can differ by a second. Full-loop latency uses only Base timestamps; the on-chain reactive leg can read higher than the full loop.
